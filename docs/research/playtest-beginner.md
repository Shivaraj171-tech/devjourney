# Fresh-eyes playtest: a complete beginner plays Seasons 1–3

**Persona:** 25, has never written code, curious but easily discouraged. Reads every story, every 📘 Learn lesson, the starter code, the CI checks and the "Done when" list, and uses hints when stuck.
**Method:** No browser. I read the content files in the order the learner sees them: `season.yaml` order; for each ticket `story.md` → `concept.md` → editable starter files and the files they import → `tests/` → `hints.md` → `questions.yaml`; `review.yaml` + `pr/` for reviews; `logs.txt` for incidents. I also skimmed `components/Onboarding.tsx` and `components/HQ.tsx`. Season 4 was skipped because other agents are editing it.
**Accuracy rule:** every problem below quotes a file and line. "Definitely" means the beginner meets syntax or a word the game hasn't taught yet and needs it to understand or finish the ticket. "Maybe" means it's untaught but not needed, or only appears in read-only files.

---

## 1. Overall verdict

1. The stories are the game's best feature. Every ticket has a person, a customer-visible symptom and a reason to care, the cast is consistent, and it's easy to read on to the next ticket. The persona would keep going through Season 1.
2. The lessons are short, warm and usually teach exactly the one idea the fix needs, and hint 3 always gives the answer, so nobody gets stuck forever.
3. The biggest problem is **order**: `def`/`return`/functions are used from ticket 1 but taught at ticket 9; lists, `len()` and `[i]` are needed in s01-t04 but taught in s01-t05; `//` shows up from s01-t07 but is only explained in a s02-t02 quiz answer; default arguments (`=None`, `=[]`) are needed in s01-t09/t10 but only get one "Watch out" sentence.
4. The second problem is a few **difficulty spikes** that break Onboarding's promise "Never two at once" (`components/Onboarding.tsx:7`): s01-t10 (mutable default arguments), s03-t01 (class + object + attribute + method + `__init__` + `self`), s03-t02 (`import`, tuple unpacking in `for a, b in d.items()`), and s03-t03, whose hint 1 sends you into a test file full of Python you have never seen.
5. Workplace jargon (PR, merge, CI, docstring, on-call, profiler) is never defined, and hints like "Try it: call…" / "print the keys" assume you know where printed output appears. Fix the order, add a short glossary/tooltip layer and say how to print, and I estimate S1 becomes a smooth ~3-hour on-ramp for a real beginner (vs. the advertised 10–15 min per ticket, which is realistic only for t01–t03).

### First-run experience (Onboarding / HQ)

- `components/Onboarding.tsx:9` "Green checks = PR merged." The first-ever screen uses "PR" and "merged" before anything explains them. Change it to "Green checks = your change goes live (a 'merged PR')."
- `components/Onboarding.tsx:7` "Each ticket teaches one new concept in a 2-minute lesson. Never two at once." This is broken at s01-t04, s01-t10, s03-t01 and s03-t02 (above), so either fix those tickets or soften the promise.
- `Onboarding.tsx:20` "one 10-minute ticket at a time" vs `HQ.tsx:101` "≈10–15 minutes per ticket". From t04 on, a real beginner takes 15–35 min, and being told it's a 10-minute task when it takes you 30 is exactly what discourages this persona. Say "10–30 minutes" or show the per-ticket estimate.
- Neither screen says where `print()` output appears or that you can experiment. Several hints assume you can ("Try it: call `create_order("Sam")`…", s01-t10 hints.md:1).

Change `t05-cart-badge/concept.md` title to "Changing lists" and keep only `.append()` + the "changes the list itself" warning (and update `ticket.yaml` `new_concept`).
